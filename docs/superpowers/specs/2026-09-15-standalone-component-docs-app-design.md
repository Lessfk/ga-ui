# GA UI Plus 独立组件文档项目设计

## 背景

现有文档站基于 VitePress，已经能够展示七个公开组件的说明、实时案例和 API 表格，但页面布局、交互和样式隔离受 VitePress 主题结构限制。组件案例与文档主题共处同一套样式环境，难以稳定保证案例呈现完全符合 `ga-ui-plus` 的真实默认效果；案例状态也缺少统一的恢复入口。

本次将 `docs` 从 VitePress 站点改造成独立的 Vue 3 应用。文档站用于组件库维护者查阅组件功能、参数、API、案例和代码片段，不承担营销官网职责，也不提供在线代码编辑器。

## 目标

- 使用 Vue 3、Vite、Vue Router 和 Element Plus 构建独立文档项目。
- 清楚介绍 `ga-ui-plus` 组件的用途、安装方式、参数、事件、插槽、实例 API 和公开类型。
- 每个案例同时提供真实组件预览、源码展开、源码复制和状态恢复。
- 文档外壳样式与组件案例样式分层，避免文档 CSS 覆盖 `ga-ui-plus` 组件主题。
- 组件导航、路由和通用页面由注册表驱动，降低后续新增组件的维护成本。
- 自动提取 TypeScript API 基础数据，并允许人工补充和覆盖中文说明。

## 非目标

- 不建设营销首页、博客、版本发布平台或在线 Playground。
- 不在浏览器内编辑、编译或执行用户输入的代码。
- 不自动承诺 Element Plus 的全部透传 API。
- 不修改 `ga-ui-plus` 现有组件公共 API 或默认主题。
- 不用自动生成结果替代人工校对复杂类型、插槽作用域和使用限制。

## 技术架构

`docs` 保持为 pnpm workspace 中的独立包，但移除 VitePress 运行时，改用标准 Vue 应用结构：

```text
docs/
├─ src/
│  ├─ app/                 # 应用入口、路由和整体布局
│  ├─ components/          # 文档通用组件
│  ├─ demos/               # 可运行的 ga-ui-plus 案例
│  ├─ generated/           # API 生成脚本的输出
│  ├─ registry/            # 组件、分类、文档和案例注册信息
│  ├─ styles/              # 文档外壳样式
│  └─ views/               # 首页、指南和组件页面
├─ scripts/
│  └─ generate-api.mjs     # 公开类型 API 提取脚本
├─ tests/
├─ index.html
├─ package.json
├─ tsconfig.json
└─ vite.config.ts
```

主要依赖：

- `vue`：应用与案例运行时。
- `vite` 和 `@vitejs/plugin-vue`：开发服务器与生产构建。
- `vue-router`：指南和组件页面路由。
- `element-plus`：文档工具控件及 `ga-ui-plus` 的基础依赖。
- `ga-ui-plus: workspace:*`：通过组件库公开入口运行案例。
- TypeScript 编译器 API：从公开类型中提取 API 基础数据。

文档项目继续配置 workspace 源码别名和 `GaUiResolver`，确保本地开发即时反映组件源码变化，同时保留按需引入路径的验证价值。

## 页面结构

文档站采用面向桌面查阅的三栏工具布局：

- 顶部栏：品牌标识、指南和组件入口、全局搜索、浅色与深色模式切换。
- 左侧栏：基础组件和业务组件分组，支持过滤、分组折叠和当前路由高亮。
- 主内容区：组件标题、简介、使用方式、案例、API 和注意事项。
- 右侧目录：根据当前页面区块生成锚点导航。

首页直接提供安装命令、快速开始和组件入口，不使用营销式 Hero。页面路由由组件注册表生成，浏览器刷新、前进和后退均保持正确页面与导航状态。

## 文档组件

### AppShell

负责顶部栏、侧边导航、正文容器、右侧目录和主题状态。主题切换只改变文档外壳的语义变量，不写入 Element Plus 或 `ga-ui-plus` 主题变量。

### ComponentPage

根据注册配置渲染统一组件文档页面，按以下顺序组织内容：

1. 组件名称、定位和适用场景。
2. 安装或引入方式。
3. 基础用法和功能案例。
4. Props。
5. Events。
6. Slots。
7. Expose API。
8. 公开类型、主题配置和注意事项。

### DemoBlock

每个案例使用独立 Vue SFC。页面通过普通模块导入运行组件，同时使用 Vite 的 `?raw` 导入同一文件源码，保证预览代码和展示代码只有一份。

`DemoBlock` 提供：

- 实时预览。
- 展开和收起源码。
- 语法高亮。
- 一键复制完整 Vue SFC。
- 重新挂载案例，使本地交互状态恢复到初始值。
- 复制失败和案例加载失败提示。

重新挂载通过递增渲染 `key` 完成，不要求每个 Demo 单独实现 reset 方法。

### ApiTable

分别展示 Props、Events、Slots、Expose 和公开类型，支持长类型折行、复制类型内容和窄内容区横向滚动。不同 API 分类不合并到同一张表中。

## 样式隔离

文档样式遵循以下边界：

- 文档外壳选择器统一以 `.ga-docs-*` 命名，避免使用影响所有元素的宽泛组件选择器。
- 不在全局覆盖 `.el-*`、`.ga-*`、`button`、`table`、`input` 等案例可能使用的元素或组件类。
- API 表格、搜索框和工具按钮使用独立文档类名控制布局。
- 案例外层 `demo-surface` 只设置边界、内边距和必要的溢出行为，不注入组件主题 CSS 变量。
- 文档深色模式默认不改变案例主题；展示主题能力时由对应 Demo 显式传入 `theme`。
- Element Plus 和 `ga-ui-plus` 的正式样式在应用入口加载，顺序保持稳定。
- Dialog、MegaMenu 和 AsideMenu 弹层继续 Teleport 到 `body`，文档布局不裁剪弹层。

## 注册表与新增组件

每个组件注册项包含：

```ts
interface ComponentDocDefinition {
  name: string
  title: string
  category: 'base' | 'business'
  description: string
  importPath: string
  demos: DemoDefinition[]
  api: ComponentApiDefinition
  notes?: DocNote[]
}
```

注册表是组件导航、搜索索引、路由和组件文档页面的数据源。新增组件时只需：

1. 添加案例 SFC。
2. 添加组件文档注册配置。
3. 补充自动 API 无法表达的中文说明和注意事项。

不需要手工修改路由表或侧边导航。

## API 数据生成

API 数据采用“自动基础数据 + 人工补充”的两层结构：

- 生成脚本读取 `ga-ui-plus` 公开类型入口，提取属性名、类型、必填状态和可识别的默认信息。
- 自动输出存放在 `src/generated`，构建和类型检查前执行生成脚本。
- 注册配置补充中文说明、Element Plus 透传关系、作用域参数、复杂默认值和使用限制。
- 人工配置按字段名覆盖自动数据，但不能引用不存在的 API 字段。
- 无法解析的公开类型、重复字段或失效覆盖会导致生成或测试失败，避免静默输出空文档。

## 搜索与导航数据流

应用启动时从注册表生成组件路由和导航分组。全局搜索索引包含组件名称、中文标题、描述和 API 名称；选择结果后跳转到对应组件或页面锚点。

页面切换时，`ComponentPage` 从路由参数取得注册项，渲染案例与 API 数据，并生成右侧目录。不存在的组件路由进入文档项目自己的 404 页面。

## 错误处理

- Demo 动态加载失败时显示案例名称和开发错误提示，不让整个组件页面空白。
- 源码复制失败时显示明确反馈，并保留可手工选择的代码区域。
- API 生成失败时终止开发准备或生产构建，输出对应组件和类型名。
- 注册项缺少标题、描述、案例或 API 数据时由结构测试报告具体路径。
- 搜索无结果时显示空状态，不修改当前路由。

## 测试策略

采用测试先行实现以下行为：

- 注册表中的组件名、路由、案例 ID 唯一。
- 每个公开组件都有简介、至少一个案例和 API 数据。
- 导航和组件路由由注册表正确生成。
- `DemoBlock` 能展开源码、复制源码和通过重新挂载恢复案例状态。
- API 人工覆盖能合并到生成数据，并拒绝不存在的字段。
- 全局搜索能够命中组件和 API 名称。
- `pnpm docs:build` 执行 API 生成、Vue 类型检查和 Vite 构建。
- Playwright 验证主要组件页面、导航、文档深色模式、弹层和多个桌面宽度。
- `ga-ui-plus` 现有单元测试继续通过。

## 工程命令

根目录继续保留统一入口：

- `pnpm docs:dev`：生成 API 数据并启动 Vue 文档项目。
- `pnpm docs:test`：执行文档注册表、组件和生成逻辑测试。
- `pnpm docs:build`：生成 API、执行 Vue 类型检查并生产构建。
- `pnpm docs:preview`：预览生产构建结果。

开发端口继续使用 `5557`。

## 迁移范围

第一版迁移当前七个公开组件：

- `GaDialog`
- `GaMegaMenu`
- `GaPagination`
- `GaTable`
- `GaAsideMenu`
- `GaSearchBar`
- `GaTablePagination`

现有 VitePress Markdown 页面中的有效说明和 Demo 逻辑迁移到新注册配置与案例目录。VitePress 配置、主题覆盖和 Markdown 页面在新项目完成并验证后删除，不保留双文档运行时。

## 验收标准

1. `docs` 是可独立开发和构建的 Vue 3 项目，不再依赖 VitePress。
2. 七个公开组件均能通过导航和搜索访问。
3. 每个组件页面包含介绍、真实预览、可展开复制源码和适用 API 分类。
4. 案例可以重新挂载并恢复初始状态。
5. 文档浅色或深色模式不会覆盖案例的 `ga-ui-plus` 默认主题。
6. 弹层组件在文档布局中不被裁剪，交互正常。
7. 新增注册项可以自动进入路由、导航和搜索索引。
8. API 自动数据和人工说明能够可靠合并，失效配置会在测试中失败。
9. 文档测试、类型检查、生产构建和现有组件库测试全部通过。
10. Playwright 检查中不存在明显溢出、重叠、空白案例或无法操作的控件。
